# Chapter 11: Your first agent

Tag: `ch11` · Compare: `git diff ch10 ch11`

## What PriorAuthBot has now

Two agents, built on Microsoft Agent Framework.

- **A policy agent** at `POST /agent`. It is chapter 10's tools in a `ChatClientAgent` with a conversation that lasts across requests. The conversation is stored per user, so only its owner can continue it. Writes still come back as pending actions for the user to approve.
- **A PTO carryover exception workflow** at `/exceptions`. Code fixes the path through it: understand the request, gather the facts, check the HR-104 rule, draft the request, ask the requester to confirm, ask the approver to decide, and record the decision. A model does two of those steps, understanding the request and writing the justification. Everything else is code that runs as the requester. The approver is the requester's manager in HR, never someone a model picked. The run waits for people at checkpoints, which live in the distributed cache, so it survives a restart and can finish on another instance.

Every agent run has a budget: a step limit, a tool call limit, a spend cap priced at hosted-model rates, a time limit, and a kill switch (`Agents:Enabled`). A run that hits one stops and says why. Each step is logged with counts only and returned with the run, so every step can be traced to a user.

## Running it

```bash
dotnet run --project samples/mock-apis/DeductibleDynamics.MockHr   # http://localhost:5180
dotnet run --project src/PriorAuthBot.Api                          # http://localhost:5080, or use the AppHost
```

The policy agent:

```bash
curl -X POST http://localhost:5080/agent -H "X-Demo-User: nurse" -H "Content-Type: application/json" -d '{"message":"What does HR-104 say about carryover?"}'
curl -X POST http://localhost:5080/agent -H "X-Demo-User: nurse" -H "Content-Type: application/json" -d '{"message":"How much PTO do I have?","conversationId":"<id from the first reply>"}'
curl -X DELETE http://localhost:5080/agent/conversations/<id> -H "X-Demo-User: nurse"
```

A carryover exception, from the nurse (Nina) to her manager (Grace, demo user `manager`):

```bash
curl -X POST http://localhost:5080/exceptions -H "X-Demo-User: nurse" -H "Content-Type: application/json" -d '{"message":"I would like to carry over 60 hours of PTO because I covered the flu surge."}'
curl -X POST http://localhost:5080/exceptions/<id>/submit -H "X-Demo-User: nurse" -H "Content-Type: application/json" -d '{"submit":true}'
curl http://localhost:5080/exceptions/reviews -H "X-Demo-User: manager"
curl -X POST http://localhost:5080/exceptions/<id>/decision -H "X-Demo-User: manager" -H "Content-Type: application/json" -d '{"approve":true,"comment":"Thanks for covering the surge."}'
curl http://localhost:5080/exceptions/<id> -H "X-Demo-User: nurse"
```

Anyone else gets a 404 for the run, as they would for a run that does not exist. HR-104's deadline is December 1, so from then until the end of the year a request stops with `past-deadline`. The offline provider (`AI:Provider=Offline`) reads the hours and reason with a few patterns, so all of this also runs with no model.

## Configuration

| Setting | Meaning |
|---|---|
| `Agents:Enabled` | The kill switch. `false` stops new agent turns and workflow runs, and the endpoints return 503 |
| `Agents:MaxModelCalls`, `Agents:MaxToolCalls` | Steps per run (default 6 model calls, 4 tool calls) |
| `Agents:MaxCostUsd`, `Agents:InputPricePerMillion`, `Agents:OutputPricePerMillion` | The spend cap per run and the prices it is counted at (default $0.01, at $0.40 and $1.60 per million tokens), even on a local model |
| `Agents:MaxRunDuration` | Wall-clock limit per run (default 2 minutes) |
| `Agents:MaxTurnsPerConversation`, `Agents:ConversationLifetime` | When a conversation is full (409), and how long an idle one is kept |
| `Agents:ExceptionRequestLifetime` | How long an exception request waits for people before it expires (default 14 days) |
| `Tools:Hr:ProfileScopes` | The delegated scope for `/me/manager` (`api://dd-hr/Profile.Read`) |

In production, register a shared `IDistributedCache` (Redis, SQL Server) so conversations, runs, and checkpoints are shared by every instance, and replace `InMemoryExceptionRegister` with the HR system of record.

## CI

| Job | What it adds in this chapter |
|---|---|
| Build and test | Budget, agent, workflow, resume, expiry, and endpoint tests on every OS; the offline agent cases in the eval gate |
| RAG eval | The 15 agent cases against `llama3.2:3b` |

The gate fails on any exception decided without its approver, any run over its limits, any held write that was not held, and any restricted fact in an agent's answer, whatever the baselines say.

## Package changes in this chapter

`Microsoft.Agents.AI` and `Microsoft.Agents.AI.Workflows` 1.28.0. The code uses only their stable APIs: TreatWarningsAsErrors turns the experimental ones (for example `AgentSessionStore`, MAAI001) into errors, so the conversation store is PriorAuthBot's own.
