# Chapter 15: Changing models safely

Tag: `ch15`, and `final` on the same commit · Compare: `git diff ch14 ch15`

## What PriorAuthBot has now

Every model and AI package can change without a surprise, and the most sensitive questions can stay on a model inside Deductible Dynamics' network.

- **models.lock.json.** Every model PriorAuthBot may load, pinned: source, exact revision, license, who reviewed it, and each file's SHA-256 (or the Ollama manifest digest). An ONNX model whose files differ from the lock, has an extra file the runtime would read, is missing from the lock, or is licensed for non-commercial use only, is not loaded.
- **An in-process model with ONNX Runtime GenAI** (`AI:Provider=OnnxGenAI`). `OnnxGenAIChatClient` builds prompts with the model's own chat template, streams, reports token usage, names its model, and runs a configurable number of generations at once. Embeddings stay on Ollama.
- **Hybrid routing** (`AI:Routing:Enabled`). A `PhiRoutingChatClient` in front of two complete pipelines sends requests with PHI to the local model: images and files, identifiers anywhere in the text, and RAG answers built from a source marked `phi: true`. The hosted branch keeps chapter 4's PHI guard. A local failure is never retried on the hosted model.
- **The audit log names the model.** Each record lists the models that answered (`provider/model`). Records without the field hash exactly as before.
- **The model is part of every cache key.** MEAI's response and embedding caches key on the messages and options, not on the model a client was built with; PriorAuthBot adds the model, so a new model is never answered from the old one's cache.
- **Re-indexing for a new embedding model.** Each chunk records its embedding model. Ingestion refuses to mix models in one collection and retrieval refuses a chunk from another model. `VectorStore:Collection` names the collection, so a new model is built into a new one beside the old (`docs/upgrade-playbook.md`).
- **A fully local profile** (`PriorAuthBot:Profile=LocalOnly`, `appsettings.LocalOnly.json`). Startup fails, listing every problem, if any setting would send data outside the network: a hosted provider, routing, Application Insights, Content Safety, the Blob archive, Document Intelligence, or an endpoint on a public host.
- **Model comparison.** The eval can time answers with no cache (`--latency`), gate a candidate against the current model's baselines (`--baseline-provider`), write a JSON summary of every run, and compare two summaries (`--compare`). `--verify-models` checks local models against the lock.
- **Package churn.** The weekly latest-packages run reports every newer version (major, minor, patch; 0.x minors count as major), keeps ASP.NET Core packages within their .NET band, and runs the offline eval gate. Preview API suppressions are listed in `docs/experimental-apis.md`, and a test fails when one is not.

## Running it

```bash
# Download Phi-4-mini (ONNX, CPU, int4, about 4.6 GB) and check every file against the lock:
python3 scripts/get-model.py phi-4-mini-instruct-onnx-cpu-int4

# The API on the in-process model (embeddings still on Ollama):
AI__Provider=OnnxGenAI dotnet run --project src/PriorAuthBot.Api

# Hybrid: hosted Azure OpenAI for most questions, PHI to the local model:
AI__Provider=AzureOpenAI AI__Routing__Enabled=true AI__Routing__LocalProvider=OnnxGenAI dotnet run --project src/PriorAuthBot.Api

# The local deployment: pull the models once, then start with Ollama and PostgreSQL on internal networks:
docker compose -f compose.local-only.yaml --profile pull run --rm pull
docker compose -f compose.local-only.yaml up -d

# Check the Ollama models you pulled against the lock:
PRIORAUTHBOT_TEST_OLLAMA=http://localhost:11434 dotnet run --project eval/PriorAuthBot.Eval -- --verify-models

# A candidate model held to the current model's bar, then the comparison:
dotnet run --project eval/PriorAuthBot.Eval -- --provider OnnxGenAI --baseline-provider Ollama --answers --redteam --latency 8 --out eval-reports/local
dotnet run --project eval/PriorAuthBot.Eval -- --compare eval-reports/eval-summary-ollama.json eval-reports/local/eval-summary-onnxgenai.json
```

## Configuration

| Setting | Meaning |
|---|---|
| `AI:Provider` | Adds `OnnxGenAI` |
| `AI:OnnxGenAI:ModelPath`, `ModelId`, `LockFile`, `VerifyHashes`, `MaxOutputTokens`, `MaxConcurrency` | The model folder; its entry in the lock; the lock; check before loading (default true); 512; 1 |
| `AI:Routing:Enabled`, `LocalProvider` | Hybrid routing (off); `Ollama` or `OnnxGenAI` |
| `VectorStore:Collection` | The collection to read and write (default `policy_chunks`) |
| `VectorStore:OnEmbeddingModelChange` | `Refuse` (default) or `Reembed` (local indexes only) |
| `Migrate:Collections` | More collections for the migration job to create and grant |
| `PriorAuthBot:Profile`, `LocalOnly:AllowedHosts` | `LocalOnly` turns on the local profile check; internal hosts outside the private ranges |

## CI

| Job | What it adds in this chapter |
|---|---|
| Build and test | The tiny ONNX model runs for real on Linux, Windows, and macOS: chat template, streaming, usage, hash and license refusals; routing end to end; the embedding model guard; cache keys; the local profile; the preview API inventory |
| RAG eval | Ollama digests recorded and checked against the lock; 8 uncached answers timed |
| Local model (ONNX Runtime GenAI) | Phi-4-mini downloaded and checked file by file, then the golden set and red team on it, gated against the Ollama baselines (verdict recorded) |
| Model comparison | The current and candidate side by side |
| Latest packages (weekly) | The package report and the offline eval gate on the newest packages |
