# Chapter 13: Observability, audit logging, and cost

Tag: `ch13` · Compare: `git diff ch12 ch13` (until earlier chapter tags exist, compare with `main`)

## What PriorAuthBot has now

End-to-end traces with no prompt text in them, an append-only audit log of every request, per-user token budgets, cost metrics and spend alerts, an answer cache partitioned by permission set, and feedback that turns into golden-set candidates.

- **OpenTelemetry.** Every chat client and embedding generator gets Microsoft.Extensions.AI's OpenTelemetry middleware, which writes `gen_ai.*` spans and metrics by the GenAI semantic conventions. PriorAuthBot adds its own `priorauthbot.ask` and `priorauthbot.retrieve` spans, with counts and flags only. Message content is off, set explicitly from `Telemetry:CaptureMessageContent`, and the API refuses to start with it on outside Development. Under Aspire, everything shows in the dashboard.
- **The request context.** The API opens an `AiRequestContext` for every request. `SecureRetriever`, the only way to documents, records every chunk it returns on it, and `MeteringChatClient`, on every model call, records the tokens. No endpoint, tool, or agent step can skip either.
- **An audit log.** One record per request, written before the response is sent: who asked, with which groups, the question, the answer, every document touched (retrieved, cited, or viewed, with its sensitivity and PHI flag), tokens, cost, status, and the trace ID. Records form a SHA-256 hash chain. In PostgreSQL, a trigger refuses updates, truncation, and deletes inside the retention period (six years by default). If a record cannot be written, the user gets a 503 instead of the result.
- **Token budgets.** A daily budget per user (larger for some groups), checked before every model call and charged after it from the provider's reported usage. A spent budget is a 429 with `Retry-After`.
- **Cost.** Token and cost counters by model and operation, priced from configuration (a local model can carry a shadow price), and spend alerts at 50, 80, and 100 percent of a daily level, as a log event (ID 1302) and a metric.
- **An answer cache.** Off by default. A question is matched against answers already given to exactly the same permission set, model, prompt version, and corpus generation, by exact text or by embedding similarity. Ingestion that changes any document empties it.
- **Feedback.** `POST /feedback` rates an answer by its audit ID; only its owner can. The audit reader role exports ratings as golden-set candidates, holding back any question with an identifier in it.

## Running it

```bash
dotnet run --project src/PriorAuthBot.AppHost     # traces, metrics, and logs in the Aspire dashboard

# Or the API alone, with the in-memory audit log:
dotnet run --project src/PriorAuthBot.Api
curl -i -X POST http://localhost:5080/ask -H "X-Demo-User: nurse" -H "Content-Type: application/json" \
  -d '{"question":"When must a positive sepsis screen be escalated to a physician?"}'
# X-Audit-Id: 0193...

curl http://localhost:5080/usage -H "X-Demo-User: nurse"
curl -X POST http://localhost:5080/feedback -H "X-Demo-User: nurse" -H "Content-Type: application/json" \
  -d '{"auditId":"<X-Audit-Id>","helpful":true}'

# The audit reader (the compliance persona has the role):
curl "http://localhost:5080/audit/users/demo-nurse/documents?phiOnly=true" -H "X-Demo-User: compliance"
curl http://localhost:5080/audit/verify -H "X-Demo-User: compliance"

dotnet run --project eval/PriorAuthBot.Eval -- --provider Offline --answers --ops
```

## Configuration

| Setting | Meaning |
|---|---|
| `Telemetry:CaptureMessageContent` | Prompts and answers on `gen_ai` spans (default `false`; Development only) |
| `Usage:DailyTokensPerUser`, `Usage:GroupDailyTokens` | Daily budgets (default 200,000; Clinical 400,000) |
| `Usage:QuotasEnabled` | Enforce the budgets (default `true`); metering runs either way |
| `Usage:Prices` | Price per million input and output tokens by model, and `Default` |
| `Usage:DailySpendAlertUsd`, `Usage:AlertThresholds` | The daily alert level and the fractions that alert (25 dollars; 0.5, 0.8, 1.0) |
| `Audit:Store` | `Postgres` (default) or `InMemory` (Development only) |
| `Audit:CreateSchema` | Create the table and triggers at startup (Aspire sets `true`; production uses a migration) |
| `Audit:RecordContent` | Keep the question and answer in each record (default `true`) |
| `Audit:ReaderRole` | The app role that may read the log (default `PriorAuthBot.AuditReader`) |
| `Audit:OnWriteFailure` | `FailClosed` (default, 503) or `FailOpen` |
| `AnswerCache:Enabled`, `SimilarityThreshold`, `TimeToLive`, `MaxEntriesPerPartition` | The answer cache (off; 0.97; 4 hours; 500) |

The API refuses to start outside Development with content capture on, with `Microsoft.Extensions.AI` logging at `Trace`, or with the in-memory audit store.

## CI

| Job | What it adds in this chapter |
|---|---|
| Build and test | Audit, telemetry, budget, and cache tests on every OS; `--ops` in the offline eval gate |
| Integration (pgvector) | The append-only table: updates, deletes, and truncation refused, and 40 concurrent appends in one valid chain |
| RAG eval | Tokens and cost per answer on `llama3.2:3b`, and the cache threshold table for `nomic-embed-text` |

The gate fails if any answer lacks a complete audit record, the chain does not verify, a span carries a question, or a cached answer reaches a different permission set.
