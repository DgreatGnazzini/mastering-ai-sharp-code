# Chapter 8: Better answers: hybrid search, reranking, and citations

Tag: `ch08` · Compare: `git diff ch07 ch08` (until earlier chapter tags exist, compare with `main`)

## What PriorAuthBot can do now

Retrieval is hybrid: every question runs as a vector search and a keyword search, each with the caller's groups inside the query, and the two rankings are merged with reciprocal rank fusion. `CPT 72148` and `HR-104` now find their policies. A reranker (a local cross-encoder or the chat model) and query rewriting can be turned on by configuration. Answers return structured citations, with document, section, page, and a link, and a minimal chat page at `/ui` shows them.

## Endpoints

| Endpoint | Chapter | What it does |
|---|---|---|
| `POST /catalog/search` | 5, 8 | Catalog search; `mode` is `Semantic`, `Keyword`, or `Hybrid` (the default) |
| `POST /search` | 6, 8 | Hybrid search; each hit shows its cosine score, keyword rank, reranker score, and link |
| `POST /ask` | 7, 8 | Grounded answer with structured citations, or a decline |
| `GET /documents/{id}` | 8 | Where a citation link lands. The same group filter as search; 404 for missing and restricted alike |
| `GET /ui` | 8 | A chat page that shows citations. Development only, with the demo personas |

## Configuration

| Setting | Default | Notes |
|---|---|---|
| `Retrieval:Mode` | `Hybrid` | `Vector` is chapter 7's behavior |
| `Retrieval:Candidates` | 20 | Candidates from each side before fusion |
| `Retrieval:RrfK` | 60 | The k in 1 / (k + rank) |
| `Retrieval:MinTermCoverage` | 0.5 | The keyword side's gate: share of the question's terms a chunk must contain |
| `Retrieval:Rerank:Provider` | `None` | `CrossEncoder` (run `scripts/get-reranker.sh` first) or `Llm` |
| `Retrieval:Rerank:Candidates` | 10 | How many fused candidates the reranker sees |
| `Retrieval:Rerank:MinScore` | 0 | Drop candidates the reranker scores below this. 0 is measured for the cross-encoder; the LLM reranker's 0 to 3 scale needs its own |
| `Retrieval:QueryRewrite:Enabled` | `false` | One extra model call per question |
| `Catalog:Mode` | `Hybrid` | For `/catalog/search` |

## Upgrading an existing index

`ChunkRecord` has two new fields, `SearchText` (full-text indexed) and `Page`. The in-memory store rebuilds at startup. For PostgreSQL, drop the old table so the connector recreates it with the new columns and the GIN index, and let ingestion run: `DROP TABLE policy_chunks;`.

## What does not port

| Store | Keyword side in PriorAuthBot |
|---|---|
| In memory | BM25 in C# over the chunks the caller may see |
| PostgreSQL | Built-in full-text search (`ts_rank_cd`, OR of the question's terms), with the group filter in the same `WHERE` |
| Qdrant | Not yet: hybrid mode runs the vector side alone. The connector's `HybridSearchAsync` uses a full-text payload match |
| Azure AI Search | Not yet: the service has BM25 and RRF built in, through the connector's `HybridSearchAsync`, and adds the semantic ranker. Chapter 14 wires it up |

## Package change in this chapter
