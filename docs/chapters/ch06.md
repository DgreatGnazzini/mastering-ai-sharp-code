# Chapter 6: Vector stores with Microsoft.Extensions.VectorData

Tag: `ch06` · Compare: `git diff ch05 ch06`

## What PriorAuthBot can do now

Chunks live in a real vector store behind one abstraction, `VectorStoreCollection<Guid, ChunkRecord>`. PostgreSQL with pgvector is the default for local runs, and Qdrant and Azure AI Search are a configuration change away. Every record carries its access list from the first insert, the group filter runs inside the store's query, and only `SecureRetriever` may query the collection, which a test enforces.

| Piece | Where |
|---|---|
| The chunk record and its security fields | `src/PriorAuthBot.Core/Retrieval/ChunkRecord.cs` |
| Store selection by configuration | `src/PriorAuthBot.Core/Retrieval/VectorStoreServiceCollectionExtensions.cs` |
| Filtered search with the caller's groups | `src/PriorAuthBot.Core/Retrieval/SecureRetriever.cs` |
| The same tests on every store | `tests/PriorAuthBot.Tests/VectorStoreIntegrationTests.cs` |
| Selective filters on HNSW, measured | `tests/PriorAuthBot.Tests/FilteredSearchExperiment.cs` |
| Only the retriever queries chunks | `tests/PriorAuthBot.Tests/RetrievalBoundaryTests.cs` |

## Choosing a store

| `VectorStore:Provider` | Settings | Notes |
|---|---|---|
| `InMemory` (default) | none | Tests and a first run. Lost on restart. |
| `Postgres` | `ConnectionStrings:priorauthbot` | pgvector 0.8 or later. The AppHost and `compose.yaml` run it. |
| `Qdrant` | `VectorStore:Qdrant:Host`, `Port` (gRPC, 6334), `ApiKey` | `docker compose --profile qdrant up -d` |
| `AzureAISearch` | `VectorStore:AzureAISearch:Endpoint` | Entra ID sign-in; your account needs **Search Index Data Contributor** and **Search Service Contributor**. |

## What does not port

| | pgvector | Qdrant | Azure AI Search |
|---|---|---|---|
| Key types | many, including `Guid` and `string` | `Guid` or `ulong` only | `string` or `Guid` only |
| Collection names | any | any | lowercase letters, digits, and dashes, so PriorAuthBot uses `policy-chunks` there |
| Group filter (`AllowedGroups.Any(g => groups.Contains(g))`) | `&&` on `text[]` | payload filter on an indexed keyword field | `AllowedGroups/any(t: search.in(t, ...))`; group names must not mix commas and pipes |
| Selective filter on HNSW | can return fewer than `top` results unless `hnsw.iterative_scan` is on (see the experiment) | filters during the graph search | filters before or during the vector search |

`Guid` is the one key type all three accept, so `ChunkRecord.Key` is a Guid derived from the readable chunk ID (`pto-policy:0003`), which is kept as `ChunkId`.
