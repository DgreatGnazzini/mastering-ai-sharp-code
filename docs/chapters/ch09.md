# Chapter 9: Evaluation and testing

Tag: `ch09` · Compare: `git diff ch08 ch09` (until earlier chapter tags exist, compare with `main`)

## What PriorAuthBot has now

An evaluation suite. The golden set grows from 24 questions to 105, 27 of them permission cases, and moves into its own project with the code that measures it. Every push measures retrieval on all 105 questions, chapter 7's vector search against chapter 8's hybrid search, checks every retrieval, prompt, and answer for leaks, and fails if anything leaks or a metric falls below `eval/baselines.json`. The RAG eval job adds LLM judges on a sample of 20 answers (relevance, groundedness, completeness, and citation faithfulness), a response cache that carries over between runs, and an HTML report.

| Piece | Where |
|---|---|
| The golden set (105 questions, synthetic, no real PHI) | `eval/datasets/golden-set.json` |
| The eval runner | `eval/PriorAuthBot.Eval/Program.cs` |
| Recall@k and MRR | `eval/PriorAuthBot.Eval/RetrievalMetrics.cs` |
| Chapter 7 against chapter 8 | `eval/PriorAuthBot.Eval/RetrievalEvaluation.cs` |
| Leak checks: retrieval, prompt, answer | `eval/PriorAuthBot.Eval/LeakageChecker.cs` |
| LLM judges with Microsoft.Extensions.AI.Evaluation | `eval/PriorAuthBot.Eval/AnswerEvaluation.cs` |
| Cached runs | `eval/PriorAuthBot.Eval/FileDistributedCache.cs` (answers and embeddings), the reporting library's response cache (judges) |
| Baselines and the regression gate | `eval/baselines.json`, `eval/PriorAuthBot.Eval/RegressionGate.cs`, `.github/CODEOWNERS` |
| Tests for the eval itself, and the echoing-model leak test | `tests/PriorAuthBot.Tests/Eval/` |
| pgvector with Testcontainers | `tests/PriorAuthBot.Tests/Infrastructure/TestDatabases.cs` |

## Running it

```bash
# No model, no network: retrieval, leak checks, the offline answers, and the gate. About 5 seconds.
dotnet run --project eval/PriorAuthBot.Eval -- --provider Offline --answers

# With Ollama (the models from chapter 7): adds the judges and the HTML report.
export PRIORAUTHBOT_TEST_OLLAMA=http://localhost:11434
export PRIORAUTHBOT_TEST_JUDGE_MODEL=qwen2.5:7b
dotnet run --project eval/PriorAuthBot.Eval -- --provider Ollama --answers
```

Reports go to `eval-reports/` (`--out` to change it): `eval-retrieval-*.md`, `eval-answers-*.md`, `eval-gate-*.md`, and `eval-answers.html`. The cache goes to `.eval-cache/` (`--cache`). Delete it to force every model call again. The exit code is 1 when the gate fails.

The pgvector integration tests start their own database when Docker is running:

```bash
PRIORAUTHBOT_TEST_TESTCONTAINERS=true dotnet test --project tests/PriorAuthBot.Tests -- --filter-class "PriorAuthBot.Tests.PostgresIntegrationTests"
```

## The golden set

| Field | Meaning |
|---|---|
| `kind` | `fact`, `exact-term`, `permission`, or `out-of-scope` |
| `chapter` | The chapter that added the case. The per-case unit tests assert chapters 7 and 8; the newer cases are measured |
| `expectedDocuments` | Must be retrieved (recall@6, MRR) |
| `mustNotSee` | Must never be retrieved for this user. Any hit is a leak |
| `expectDecline` | PriorAuthBot must answer "I don't know" |
| `answerMustContain` / `answerMustNotContain` | Checked on the answer. A restricted fact in an answer is a leak |
| `expectedAnswer` | Ground truth for the completeness judge |
| `answerEval` | In the sample the LLM judges score in CI |

The users are the chapter 7 personas plus `staff` (AllStaff only).

## The gate

| Check | Rule |
|---|---|
| Leaks in retrieval, prompts, or answers | Must be 0. Not in the baselines file, so no edit can relax it |
| Recall@6, MRR, declines kept | At most 0.02 (declines 0.05) below the baseline |
| Judge scores (1 to 5) | At most 0.5 below the baseline |
| Citation faithfulness, answers containing the expected fact | At most 0.10 below the baseline |
| A metric no judge could score | Fails |

Each run prints its numbers as a baseline entry. Changing `eval/baselines.json` or the golden set needs a CODEOWNERS review.

## CI

| Job | What it adds in this chapter |
|---|---|
| Build and test | The offline eval and gate on Linux; the eval's own unit tests and the echoing-model leak test on every OS |
| Integration (PostgreSQL + pgvector) | Starts pgvector with Testcontainers instead of a service container |
| RAG eval (golden set on Ollama) | Runs the eval project with judges, restores and saves `.eval-cache`, uploads `eval-answers.html`, and fails on the gate. The chapter 7 golden set step moved into it |
